## What went wrong for the operator (the defects, in his words and in the code)

1. **"I couldn't steer it at all while it was working."** After his decision at 10:40:53 no message of his ever reached the seat. The seat spent ~half the session inside foreground `sleep 480`/`sleep 540; ssh …` polls (single Bash calls up to 9 minutes). Code: the composer textarea and send button are `disabled` whenever `running` (`media/workbench.js:509,512`); `sendPrompt` rejects with "That conversation already has a lane running." (`src/extension.ts:511-513`); the door process is ONE-SHOT — `child.stdin.end(invocation.stdin)` right after the prompt (`src/adapters/cliAdapter.ts:1084-1087`), so there is no channel to deliver a follow-up. Only Stop exists (kills the tree).
2. **"It worked on its own without letting me know what's going on."** The seat behaved like a detached lane (never yield, poll in the foreground) because the prompt wrapper ("Act as the GeneralStaff orchestrator…", `src/adapters/cliAdapter.ts`) carries no seat-conduct rules, and the UI shows nothing about what a running tool call is doing or for how long.
3. **"It constantly scrolled to the top."** `render()` (`media/workbench.js:770-799`) rebuilds the whole app with `app.innerHTML = …` on EVERY event — `run-event` (each tool start/result card, line 1144), `context-usage` (each meter tick, line 1135), notices, notes — and restores scroll via a rAF "within 72px of bottom" heuristic that races layout. Only `conversation-delta` patches in place (1008-1025).
4. **"The chat input box is too big; hard to read what the AI is saying."** Composer: textarea `min-height:62px`, `rows=3`, `resize: vertical` with no max (`media/workbench.css:2441-2460`); the five selects in `.composer-selects` wrap onto extra rows in a narrow sidebar (css:1141-1146) above a 30px context row and hint text; `.message-stream` is the only flexed region (css:1789-1791) so composer growth eats the transcript. REGATE-OPUS.md:65 already found ~1 turn visible at 1100×700.

- **M2 Seat conduct (the prompt wrapper).** Add a SEAT CONDUCT block to the wrapper, before "Operator request": (a) work in rounds; end every round — at most ~10 minutes of activity, or immediately when a dispatch/harvest lands — with a 3-6 line plain-English status: DONE / RUNNING (lane + sentinel + expected time) / NEXT / NEEDS YOU, then hand control back; (b) never block inside a tool call: no `sleep` over 60 s, no polling loops in a foreground call — waits go to a background `until` loop (`run_in_background`) or a Monitor and the seat reports the event in a new round; (c) filter shell output; (d) the decision-card protocol is unchanged. The operator reads plain English; no jargon dumps.
- **M3 Live activity strip.** While a run is live, a one-line strip above the composer shows: current tool + first line of its command/path, elapsed mm:ss for that call, total run time, and "woke on: <background task> finished" when a queued task-notification resumed the seat. Streamed assistant text still renders as it arrives. When the seat ends a round, the strip reads "idle — your turn".
